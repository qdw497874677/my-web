# ADR 0001: 单进程 TypeScript 后端与 SQLite

## Status

Accepted

## Context

林间刊物是单刊物、单所有者产品，写入频率低，主要流量来自公开内容读取。后端需要替换浏览器 localStorage，提供身份验证、内容管理、图片上传、公开查询和订阅收集。项目现有前端使用 TypeScript，当前没有既有部署平台或数据库约束。

需要在尽快获得完整、可测试的后端与为未来规模预留复杂基础设施之间取舍。

## Decision

后端采用单进程 Node.js TypeScript 应用：

- Fastify 提供 HTTP API、Cookie 会话和文件上传入口。
- SQLite 作为唯一关系数据库，并启用外键约束和事务。
- 数据访问集中在 repository 层，不把 SQL 或 SQLite 特性暴露到 HTTP handlers。
- 图片文件通过存储适配器管理；首个实现使用本地文件目录，数据库只保存资产元数据和稳定引用。
- 公开 API 与编辑部 API 位于同一应用；编辑部写接口统一要求所有者会话。
- 数据库迁移、所有者账户初始化和演示内容导入由独立命令完成。

## Consequences

单机即可开发和部署，不依赖外部数据库与对象存储，适合当前单所有者、低写入量场景。事务可以直接维护相册顺序、精选顺序、引用保护和发布状态约束。

SQLite 和本地图片目录要求部署环境提供持久磁盘，不能直接水平扩展到多个无状态实例。若未来改为多实例部署，应在保持 repository 与存储适配器接口的前提下迁移到 PostgreSQL 和对象存储。

本决策不引入微服务、消息队列、缓存层或后台任务系统。排期文章是否公开由查询时的刊物时区规则判断，不依赖定时任务修改状态。
